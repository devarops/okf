The pattern works in iterative cycles within a single iteration.
Each cycle has two steps: implementation and verification.
The implementation step uses an LLM agent to write code or make changes.
The agent starts each cycle with a fresh context and no memory of previous passes.
This deliberate amnesia forces state to persist externally in the specification.
The specification is written in the Lean language as a formal specification.
The Lean formal specification is the canonical source of truth.
Optional human-readable documents can be derived from the Lean spec.
The verification step checks the current state against the Lean specification.
The Lean kernel performs this verification deterministically.
It provides a mathematical guarantee of correctness.
If verification fails, the cycle repeats with the failure information as input.
If verification passes, the cycle terminates successfully.
The pattern is independent of the implementation method.
It works with LLM agents, human developers, or any combination.
The Qed tool implements this pattern with Lean 4 as the verification engine.
Talks at the Software Verification in Lean 2026 workshop explored correct and computable specifications in Lean.
